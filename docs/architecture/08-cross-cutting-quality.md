# 横切架构、安全与质量保障

> 文档类型：Cross-cutting Architecture  
> 适用范围：V1 Mac 单机版、V2 Windows 共享版  
> 目标：把安全、性能、可观测性、数据质量、测试和恢复要求落到统一架构边界

## 1. 横切原则

1. 数字计算、证据检索和模型生成分层。确定性数据不交给语言模型心算。
2. 所有写任务单写。V1 本地单用户也保持全局锁，以便提前验证 V2。
3. 所有已发布结果必须绑定 `snapshot_id`、来源文件版本、解析器版本和模型版本。
4. 外部网站、MinerU、Qwen 和 Bloomberg 都视为不稳定依赖，必须有超时、重试、降级和明确错误。
5. 代码、配置、密钥、业务数据、日志和备份分目录存放。
6. 基础查询与统计在关闭外部生成模型时仍可用。
7. 任何“零”都必须可区分于“缺失”“未披露”“未解析”和“已终止”。

## 2. 身份、授权与密钥

### 2.1 权限模型

| 能力 | V1 | V2 |
|---|---|---|
| 登录 | 本机单用户，可自动建立本地会话 | 每人独立账号，管理员与投研用户分权 |
| 查询、搜索、问答 | 唯一本地用户可用 | 登录用户可读当前快照 |
| 创建写任务 | 本地用户 | 投研用户；全局单写锁 |
| 取消任务 | 本地用户 | 发起人或管理员 |
| 管理模型 Key | 本地用户 | 用户管理个人 Key；管理员管理平台 Key |
| 发布与回滚 | 本地验收人 | 管理员 |
| 数据库直连 | 仅应用和本机维护 | 仅应用和 Tableau 只读账号 |

### 2.2 密钥边界

- Qwen、MinerU 和 Bloomberg 凭据只在服务端使用；
- 平台默认 Key 与用户个人 Key 分开保存；
- 用户只能覆盖平台白名单中的同一模型 Key，不能修改 provider、Base URL 或 model ID；
- V1 优先使用 macOS Keychain，开发环境可用环境变量注入；
- V2 使用 Windows Credential Manager/DPAPI 或应用层信封加密；
- 日志、异常、HTTP trace、Agent 工具输入和导出文件不得包含明文 Key；
- Key 更新需要记录操作人和验证时间，不返回明文；
- 个人 Key 失败时暂停并询问用户，未经确认不得切换公司 Key。

### 2.3 网络与数据库边界

- V1 只监听 `127.0.0.1`；
- V2 通过公司局域网或 VPN 访问，外部入口必须使用 HTTPS；
- PostgreSQL 不暴露公网；防火墙只允许应用主机和批准的 Tableau 客户端；
- Tableau 使用只读角色和稳定视图，不允许访问凭据表、任务锁和 staging 业务表；
- Agent 不接受任意 URL、任意 SQL 和任意 Shell；
- 下载器只访问已注册域名和允许的重定向范围，防止 SSRF 和任意文件写入。
- 正式使用前确认 MinerU、Qwen 和 Bloomberg 的数据驻留、日志保留、禁止训练和账号授权条款。

## 3. 可观测性

### 3.1 结构化事件

每个任务和模型调用生成不可变事件，至少包含：

```text
event_id
occurred_at
job_id
batch_id
fund_id
step
status
duration_ms
attempt_no
error_type
error_code
source_adapter
adapter_version
model_profile
credential_scope
input_tokens
output_tokens
estimated_cost
snapshot_id
```

敏感字段按白名单采集。原始问题、全文内容和 API Key 默认不写入普通运行日志。

### 3.2 看板指标

| 指标 | 用途 | V1 | V2 |
|---|---|---|---|
| 任务总数、成功、部分失败、失败 | 判断整体健康 | 支持 | 支持 |
| 覆盖率及 90% 目标差额 | 业务验收 | 支持 | 支持 |
| 文档来源与新鲜度 | 发现过期或缺口 | 支持 | 支持 |
| 适配器错误率 | 定位官网结构变化 | 支持 | 支持 |
| PDF 解析失败率 | 判断 MinerU 或文件质量 | 支持 | 支持 |
| 结构化校验告警率 | 发现字段或表格问题 | 支持 | 支持 |
| Qwen/MinerU 延迟、限流、token、费用 | 控制外部依赖 | 支持 | 按用户和任务汇总 |
| 查询 P50/P95 | 验证 2 秒和 2n 秒目标 | 支持 | 支持 |
| 任务锁持有者与等待时长 | 解释多用户排队 | 本地状态 | 共享可见 |

### 3.3 日志与追踪

- 日志采用 JSON，包含 `request_id`、`job_id` 和 `batch_id`；
- API、Worker 和 Agent 之间传播 trace ID；
- 外部请求记录目标域名、状态码、耗时和重试次数，不记录凭据；
- 失败时保留脱敏后的请求参数、响应摘要、适配器版本和截图/HTML 片段；
- 任务事件写入 PostgreSQL `job_events`，终端日志只用于诊断。

## 4. 性能与容量

| 场景 | V1 目标 | V2 目标 |
|---|---|---|
| 单基金查询 | P95 ≤2 秒 | P95 ≤2 秒 |
| 批量确定性统计 | P95 ≤2n 秒 | P95 ≤2n 秒 |
| 当前 775 只全量更新 | ≤2 小时，缓存可用、外部服务正常 | 保持 |
| 最多并发读取 | 1 | 3 |
| 最多并发写入 | 1 | 1 |
| 文档资产 | 现有约 1.6 GB、6,000 余个文件迁入 | 共享文件和增量缓存 |

### 4.1 全量更新时间预算

2 小时是实现目标，不是未经验证的承诺。建议初始预算：

| 阶段 | 预算 | 优化手段 |
|---|---:|---|
| 名单冻结与来源解析 | 5 分钟 | 主数据缓存、来源映射 |
| 并行下载 | 30 分钟 | 按域名限流、连接复用、断点重试 |
| MinerU 解析 | 55 分钟 | PDF 哈希缓存、有限并发、失败降级 |
| Qwen 结构化 | 20 分钟 | 只提交必要页面、结构化缓存 |
| 校验与发布 | 10 分钟 | 流式校验、批量写入、单事务切换 |

最终并发数必须以官网承载能力、MinerU/Qwen 限额和真实 775 只名单压测结果为准。缓存命中率、网络延迟和外部服务限流必须记录在性能报告中。

### 4.2 查询优化

- 所有查询先绑定 `current_batch_id`；
- `funds`、`document_versions`、`fund_metrics` 和标签关联建立组合索引；
- 向量查询前先按基金、报告期和文档类型缩小范围；
- 高频概览统计可由已发布批次物化视图提供；
- ECharts API 和 Tableau Desktop 只读视图使用稳定字段名和明确快照语义；
- 不把 N+1 请求隐藏在 API 聚合层。

## 5. 数据质量与证据质量

### 5.1 文件质量门

- PDF 文件头、页数、MIME、大小和哈希有效；
- 报告期、基金名、伞名、来源 URL 和文件类型可识别；
- 文件与任务基金存在明确匹配证据；
- 同一基金同一报告期的新旧版本可区分；
- 过期、已终止和替代财报状态必须显式记录。

### 5.2 结构化质量门

- 日期、币种和单位符合 Schema；
- 权重和占比在允许误差内；
- 规模、净值、收益和流量不可把空值当零；
- 关键指标保存来源页码和原文片段；
- 低置信度、缺字段和模型冲突进入 `review`；
- 模型不得覆盖原始解析结果，修正作为新版本记录。

### 5.3 回答质量门

- 数值答案有 SQL 查询和公式口径；
- 文档解释有可打开的文档版本和页码；
- 引用必须支持对应 claim，而不是仅与问题主题相关；
- 证据低于阈值时返回“现有资料不足”；
- 回答保存快照、工具调用、模型和引用；
- 同一快照上的相同查询应可重放。

## 7. 备份、恢复与发布

### 7.1 数据恢复

- 每个成功发布批次后执行数据库备份和文件清单快照；
- 数据库备份必须与文件目录 `batch_id` 对应；
- 恢复演练至少验证“数据库恢复 + 文件路径恢复 + 当前快照指针”一致；
- staging 和导出文件可重建，原始 PDF、解析结果、结构化结果和审计记录属于正式资产；
- 备份和日志不得进入源码仓库。

### 7.2 发布回滚

1. 停止接收新任务，等待或取消当前写任务；
2. 备份当前数据库和数据目录；
3. 切回上一已验证代码版本；
4. 只降级向前兼容数据库迁移，禁止破坏性回滚；
5. 切回上一已发布业务快照指针；
6. 执行健康检查、单基金查询、Tableau 刷新和问答冒烟。

### 7.3 建议恢复目标

以下为待业务确认的架构假设：

| 指标 | 建议值 | 说明 |
|---|---:|---|
| RPO | ≤24 小时 | 每日备份；若允许重下外部报告可缩短数据损失 |
| RTO | ≤4 小时 | 单机服务器恢复和验证目标 |
| 发布回滚 | ≤30 分钟 | 不包含外部服务不可用 |

## 9. 验收阻断项

以下情况不得视为“验收通过”：

- 只展示技术演示，无法完成选择基金到报告导出的闭环；
- 将 staging 或部分失败数据暴露为当前快照；
- 无引用或引用页码错误仍输出确定结论；
- 以 0 代替规模、收益或流量缺失；
- 三名用户可同时写正式数据库；
- 个人 Key 或平台 Key 出现在日志、前端或导出中；
- 只在一台机器手工启动成功，没有可重复安装、迁移和恢复流程；
- Windows 版本未执行浏览器、路径、编码、服务启动和备份恢复冒烟。
