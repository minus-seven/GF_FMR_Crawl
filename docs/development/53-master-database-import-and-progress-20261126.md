# 综合资料库导入与任务进度修复

## 修复内容

- `read_hkex_workbook` 不再假设主数据永远是历史快照的 2,479 行；基金行数由当前工作簿动态确定。
- 仍保留三项结构校验：主数据至少有一行、基金代码非空、基金代码唯一。空表或错表不会进入导入流程。
- 综合资料库旧爬虫输出的 `[已处理/总数]` 被转换为标准 `job.stage` 进度，并同时保留 `job.backfill` 原始日志。
- API 在任务进入校验/发布阶段后仍读取综合资料库下载阶段的最终进度，因此不会回退到数据库旧快照的基金数。
- Web 的右上角任务提示、任务列表数量、Run detail 进度条和事件控制台均展示动态总数；Run detail 额外展示参考工作簿、更新方式、缓存策略和自动落库策略。
- 缓存下载名复用参考文件前缀并替换为更新日期，例如 `HKEX基金综合资料库_完整_20261126.xlsx`；内部 `HKEX基金综合资料库_latest.xlsx` 仍作为自动落库别名保留。

## 验收口径

当前任务生成的工作簿实际解析为 2,504 只基金、2,504 个唯一代码；不再因历史 2,479 行断言失败。动态工作簿、空代码、重复代码和爬虫进度解析均有回归测试。
