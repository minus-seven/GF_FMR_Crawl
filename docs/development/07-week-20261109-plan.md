## 1. 本周目标

在已经完成的 PostgreSQL、任务流水线、Web 看板和页级知识检索底座上，完成一个可验收的最小知识消费闭环：

```text
已发布结构化数据
→ SQL 优先查询
→ 页级全文/向量证据检索
→ 带来源和页码的回答
→ 证据不足时拒答
→ 用户确认后创建受控任务
→ 任务状态和新快照可追踪
```

本周结束时，至少能够演示：

1. 对单只基金和多只基金提出事实、比较、趋势问题；
2. 数值优先来自结构化数据库，文字解释返回报告期、文档和页码；
3. 找不到有效证据时明确返回“资料不足”，不生成猜测值；
4. 从自然语言意图生成任务计划，展示范围、阶段、基金数和预计耗时；
5. 写任务必须经过确认，确认后才能进入现有任务队列；
6. 复核、来源管理、月报/半年报/年报结构化回归不被新功能破坏。

### 周二 11/10：SQL 优先问答后端与证据契约

状态：已完成（API、契约、拒答语义和真实快照冒烟已通过）。

目标：在现有确定性查询和知识检索之上完成最小问答 API，不先做开放式 Agent。

任务：

- 增加问题类型识别：结构化事实、跨基金比较、原文解释、趋势和无答案；
- 实现 SQL 优先路由：能由指标/持仓/配置直接回答的问题不调用模型；
- 对需要文字解释的问题调用全文或 hybrid 检索；
- 定义回答、限制、快照、证据片段和引用字段；
- 为每个事实性 claim 绑定至少一个文档版本、报告期、页码和内容哈希；
- 增加证据不足、报告期冲突、跨基金证据混用和隐藏来源误用的拒答规则；
- 本地 Qwen 只用于问题解析和证据归纳，不能绕过数据库质量门。

交付物：

- `POST /api/chat` 或等价问答接口；
- 问答与引用 Pydantic schema；
- 单基金、跨基金、无答案和报告期冲突测试；
- 问答服务运行说明。

验收门：

- 结构化事实问题不依赖外部模型也能回答；
- 文字结论返回可点击的文档、报告期和页码；
- 没有有效证据时返回明确拒答状态；
- 不允许跨基金、跨报告期或跨快照拼接证据。

## 5. 风险与降级策略

| 风险 | 处理 |
|---|---|
| PostgreSQL/API 未启动 | 先修复运行环境；问答只做单元测试，不做端到端验收 |
| 本地 Qwen 不可用 | SQL/全文检索继续可用；模型相关问题返回明确降级状态 |
| PDF 无页码或证据不完整 | 不生成确定性结论，标记待复核 |
| 外部站点不可达 | 保留原始错误和重试边界，不伪造来源成功 |
| 向量服务不可用 | hybrid 降级全文检索，并在响应中标记 limitation |
| 全链路时间不足 | 优先保证 SQL 问答、引用、拒答和任务确认，导出与高级 Agent 顺延 |

## 6. 周末完成定义

本周只有同时满足以下条件，才标记为“知识问答与受控 Agent 闭环完成”：

1. API、Worker、Web 和数据库在同一环境中可启动；
2. 至少一条真实基金问答返回有效页码证据；
3. 至少一条证据不足问题被正确拒答；
4. 至少一次任务创建经过计划确认；
5. 现有结构化和来源管理回归通过；
6. 所有未完成项、测量值和数据缺口已写入验收报告。
